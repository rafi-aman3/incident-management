# EHS Platform — Functional Verification (no UI/UX critique)

**App:** `http://localhost:3001` — `v0.1 · Phase 0`
**Date:** 2026-05-06
**Tester actions used to verify:**
* Filed a real S1 incident as Sam Supervisor (`INC-2026-0035`, `INV-2026-0009`).
* Typed into Findings + 5-Why, waited > autosave window, reloaded, refetched the page from the server, and inspected outgoing network calls.
* Clicked every action button on the new incident detail (`Override severity`, `Assign owner`, `Escalate`).
* Clicked CAPA rows and tab filters; opened the document-attach modal on an incident.
* Watched the JS console for runtime errors throughout.

For each spec function: **WORKS** = behaves as the spec promises end-to-end; **BROKEN** = exists in UI but does not actually do the thing; **MISSING** = no implementation reachable in the build; **UNTESTABLE** = the action requires an upstream broken thing first, so I could not exercise it.

## Functional verdict (one screen)

| Stage                        | Functions WORK                              | Functions BROKEN                                       | Functions MISSING / UNTESTABLE                                                           |
|------------------------------|---------------------------------------------|--------------------------------------------------------|------------------------------------------------------------------------------------------|
| 1. Worker reports            | 3                                           | 0                                                      | 1 (no-site accounts blocked)                                                             |
| 2. Auto-classify + paperwork | 3                                           | 2 (OSHA clock display, OSHA 301)                       | 4 (in-app/email/SMS notifications x2)                                                    |
| 3. Supervisor triage         | 2 (open incident, Assign owner)             | 2 (Override severity, Escalate)                        | 2 (red banner, audit log)                                                                |
| 4. EHS Mgr investigation     | 2 (Kanban lanes, frozen summary carry-over) | 3 (5-Why autosave, Findings autosave, tab first-click) | 6 (assign-lead, add-team, evidence upload, photo auto-tag, SDS auto-attach, Assign CAPA) |
| 5. CAPA Owner                | 1 (list view)                               | 1 (detail page 404)                                    | 1 (mark complete + proof)                                                                |
| 6. Verifier                  | 0                                           | 1 (Pending verification filter)                        | 4 (DB rule unverifiable, notification, side-by-side, verdict)                            |
| 7. Closure cascade           | 0                                           | 0                                                      | 4 (no close buttons + no safety-bulletin)                                                |

**Net:** the only end-to-end functional path from the spec that the build actually completes is **Stage 1 + most of Stage 2** — Worker fills the wizard → severity/track classified → incident + investigation rows created. Past that, regulatory clocks, notifications, OSHA 301 generation, evidence handling, CAPA assignment, the entire CAPA owner→verifier loop, the closure cascade, and the safety-bulletin nudge are either broken (button exists, does nothing) or missing (no implementation reachable). Two specifically-claimed behaviours — **5-Why and Findings autosave** — are written into the UI copy ("autosaves 1 second after you stop typing") but were proved with reload + server fetch + network capture to **not persist anything**.
